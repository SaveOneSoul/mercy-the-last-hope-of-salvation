# Logos Old Testament Greek Production Integration

This milestone promotes the already accepted **Old Testament Expansion Phase 1B** Greek witness set into a production package and API layer. It does not change the Douay-Rheims English corpus, the OSHB/WLC Hebrew-Aramaic evidence, or the Greek New Testament package.

## Catholic/Douay-Rheims mapping contract

The canonical reference system is the installed 73-book Douay-Rheims Catholic corpus. Source Greek verse boundaries are never rewritten merely to force a Douay-Rheims one-to-one alignment.

Exact source-reference mapping is allowed for:

- Tobit
- Judith
- 1 Maccabees
- 2 Maccabees
- Wisdom
- Sirach
- Baruch 1–5
- Epistle of Jeremiah -> Baruch 6
- Theodotion Daniel 3:24–90
- Theodotion Susanna -> Daniel 13:1–64

Component-range mapping is retained where exact source/Douay boundaries are not safely equivalent:

- Greek Esther additions
- Theodotion Bel and the Dragon -> Daniel 14

The accepted Theodotion Bel witness has **36 source verse divisions**, while Douay-Rheims Daniel 14 has **42 verses**. The production API therefore returns the preserved 36-source-verse component and identifies the requested Catholic range without manufacturing six Greek verse boundaries.

Daniel keeps **Theodotion** as the Catholic integration lane while **Old Greek** is returned independently as a preserved parallel witness. The two are never silently collapsed.

## Production API

The router is mounted under `/api/logos/ot-greek`.

```text
GET /api/logos/ot-greek/catalog
GET /api/logos/ot-greek/source-rights
GET /api/logos/ot-greek/interlinear?reference=Tobit%201:1
```

Representative canonical requests:

```text
/api/logos/ot-greek/interlinear?reference=Wisdom%201:1
/api/logos/ot-greek/interlinear?reference=Baruch%206:1
/api/logos/ot-greek/interlinear?reference=Daniel%203:24
/api/logos/ot-greek/interlinear?reference=Daniel%2013:1
/api/logos/ot-greek/interlinear?reference=Daniel%2014:1
/api/logos/ot-greek/interlinear?reference=Esther%2015:1
```

The API exposes source surface text and mapping/provenance metadata only. It does **not** invent or attach Greek glosses, lemmas, morphology, or transliteration for this corpus.

## CI and promotion

Pull requests must rebuild Phase 1B from its immutable pins, validate it, build a temporary production package, and run the production package validator. On `main`, the corpus workflow vendors the deterministic production package and commits it only if the generated bytes differ.

The production validator enforces:

- accepted merge identity
- 15 witnesses / 5,337 source verse records
- exact source commit/tree pins
- per-file Git blob identity and SHA-256 evidence
- CC BY-SA 4.0 isolation
- exact accepted versification-map copy
- separate Old Greek/Theodotion witness handling
- 36-source-verse vs 42-Douay-verse Bel boundary
- no English Scripture text inside the package
- no fabricated gloss, lemma, morphology, or transliteration layer

## Frontend boundary

This milestone does **not** change the public Logos frontend. Frontend integration is a later milestone after the production corpus has been generated on `main`, the backend has been deployed, and the live Cloud Run endpoints have been verified.
